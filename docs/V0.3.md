# v0.3 SkillBench interoperability

v0.3 adds a narrow consumer bridge from verified `skillbench.harness-observation/v1` payloads into the existing AHI observation model.

## Normalization

For scoreable executions:

- SkillBench `benchmark.id` -> AHI `benchmark`;
- `benchmark.version` -> `benchmark_version`;
- `caseId` -> `task_id`;
- `trial` -> `trial`;
- model and harness identity/version are preserved;
- `pass` -> `success=true`;
- `fail` -> `success=false`;
- cost, latency, tokens, finish timestamp and evidence URI are preserved when present.

The importer reserves `configuration._skillbench` and records the portable observation schema plus exact skill-source SHA-256 there. This makes skill-source changes part of AHI configuration identity instead of silently coalescing results from different skill revisions.

## Non-scoreable diagnostics

`error` and `skipped` normalize to `ahi.skillbench-import/v1` diagnostics, not AHI observations. They therefore do not enter success-rate cells as false outcomes.

## Integrity checks

The importer validates:

- schema identity and required IDs;
- SHA-256 shape;
- outcome vocabulary;
- offset-aware timestamps and ordering;
- exact agreement between `latencyMs` and elapsed timestamps;
- non-negative telemetry;
- deterministic fingerprintability of configuration/environment;
- absence of a producer-supplied reserved `_skillbench` key.

## Bundle boundary

AHI does not claim to independently reproduce SkillBench bundle-v1 canonical hashes in Python. The interoperable input is one already-verified portable observation payload. This avoids false cross-language hash equivalence caused by runtime-specific JSON number serialization.

## CI model

The consumer fixture is pinned in this repository so normal CI has no network or cross-repository checkout dependency. Contract drift is therefore explicit: a producer schema change requires a reviewed fixture/parser update rather than silently changing historical benchmark interpretation.
